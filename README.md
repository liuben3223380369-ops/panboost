# PanBoost — 全网盘通用多线程加速下载器

零依赖（纯 Python 标准库，Python 3.8+）、单文件、开箱即用的多线程下载器。
基于业界验证过的最优方案：**你的登录态（Cookie）+ 真实下载直链 + HTTP Range 分段并发 + 断点续传**——
这正是 IDM / Aria2 / Motrix / FluxDown 等工具加速网盘下载的同一原理，但 PanBoost 针对"网盘场景"
内置了 Cookie 管理、UA/Referer 伪装、直链自动识别，适用于**任何网盘**。

v1.2 引入**反风控引擎**；v1.3 深化为**十九机制**（三态熔断、403语义分类、拟人化流量、跨会话域级记忆、
全局限速、审计摘要）；v1.4 新增 **JS Cookie 挑战自动应答**——中科大镜像式"Verifying your browser"
验证页可无浏览器自动通过（实测 3.5GB ISO 下载全程零人工干预）。

v1.5 聚焦**下载稳定性与域级学习**：块级看门狗击杀僵尸连接、块内断点续传（大块失败不整块重来）、
崩溃一致性进度文件 v3、磁盘预检、全局错误预算（防请求风暴）、域级并发学习（二次运行直接从上次
AIMD 收敛值起步）、单线程 `.pbpart` 续传、无进展熔断（永久 429 不再无限重试挂死）、
WAF 拦截页识别（华为云 CloudWAF 418 给出明确等待指引而非模糊报错）。

v1.6 聚焦**性能与压力验证**：TCP_NODELAY/SO_RCVBUF socket 调优、1MB 写缓冲聚合（pwrite 系统调用
-75%）、字节感知连接复用（满 32MB 才换连接，摊薄 TLS 握手）、脏标记保存（微小块场景消除每秒
JSON 序列化）、延迟感知预防性降载（TTFB 拥塞检测）、双进程文件锁（flock 杜绝并发写坏文件）、
探测期瞬时限流重试、`--input` 批量下载队列。9 场景压力测试（混沌/RST 风暴/kill-9 循环/双进程
竞争/内存泄漏）全部通过，见 `tests/stress_test.py`。

> 📊 对标 aria2(43k★)/Motrix(57k★)/Gopeed(27k★)/LinkSwift(24.5k★) 等主流项目的生态调研与技术对比，
> 见 [RESEARCH.md](RESEARCH.md)——PanBoost 是唯一内置 AIMD 自适应并发 + 403 熔断的命令行下载器。

## 线程数怎么选（重要）

**有效并发 = 你的总带宽 ÷ 单连接被限的速度**。超过这个数，线程再多也不会更快——
它们只是在分抢同样的总带宽。这就是为什么不建议无脑 512/1024 线程：

1. **无收益**：16 线程已打满 21MB/s 出口时，1024 线程还是 21MB/s（实测验证）
2. **有代价**：TCP 慢启动 + TLS 握手开销；客户端调度开销
3. **有风险**：高并发是网盘/CDN 风控最敏感的信号——实测 512 并发触发 CDN 封 IP（403），
   且高并发下曾收到错位响应导致数据损坏（已用三重防护修复，见下）
4. **正确做法**：`--auto` 实测服务器限速特征后自动选线程数（推荐），或按经验手动：
   网盘限速狠（单连接 <1MB/s）用 64~128；镜像站/不限速源 8~16 足够

## 反风控引擎（v1.5，二十二机制）

1024 线程最大的风险不是速度，而是**触发风控封禁**。引擎按"预防 → 响应 → 恢复 → 可观测"四层组织：

### 触发前预防（让流量看起来像礼貌的浏览器）

| # | 机制 | 作用 |
|---|---|---|
| 1 | **平滑爬坡** | 并发上限从 8 开始每秒翻倍（8→16→…→1024），杜绝瞬时连接风暴——风控的第一信号 |
| 2 | **建连限速+抖动** | 令牌桶限制新连接速率（`--conn-rate` 默认 64/s），通过后随机停顿 0~80ms，握手不再步调一致 |
| 3 | **拟人化请求头** | PersonaKit 补全 Accept/Accept-Language/Sec-Fetch-* 浏览器头；Accept-Encoding 强制 identity（Range 下载必须禁压缩） |
| 4 | **TLS 指纹缓解** | Chrome 风格 cipher 序列，缓解 JA3/JA4 客户端指纹（完整指纹需 curl_cffi，纯标准库做到的部分） |
| 5 | **块乱序入队** | 请求顺序不再 0,1,2... 单调递增，削弱机器式顺序扫描特征 |
| 6 | **连接寿命限制** | 每条 keep-alive 连接最多服务 6 块即重建，模拟浏览器换连接行为 |
| 7 | **全局限速** | `--limit 4M` 令牌桶整形总吞吐，主动配合服务器承受能力 |

### 触发时响应（收到限流/拒绝信号）

| # | 机制 | 作用 |
|---|---|---|
| 8 | **AIMD 自适应降速** | 429/503/403 → 并发上限立即减半，自动收敛到服务器容忍值（实测：并发上限16的服务器，1024线程客户端峰值恰好16、从未超发） |
| 9 | **Retry-After 合规** | 严格遵守服务器返回的 Retry-After（秒数或 HTTP 日期），不多打一枪 |
| 10 | **指数冷却+随机抖动** | 无 Retry-After 时按 30s→60s→120s 指数冷却；等待加 ±10~30% 抖动，避免多线程同步重击（惊群） |
| 11 | **403 语义分类** | 区分"直链过期/签名失效"（重试无意义，提示重新取链）与"风控封禁"（可降速恢复），不浪费熔断名额 |
| 12 | **UA 轮换** | worker 收到 403 时在 8 个 UA 池中轮换（浏览器/aria2/curl 混合），探测期被拒也自动回退 |
| 13 | **无进展熔断** | 429/503 持续且 30 秒零成功块 → 进入 OPEN 熔断走有界退出，杜绝永久限流下的无限重试挂死；正常 AIMD 收敛始终有成功块穿插，不会误熔断 |
| 14 | **WAF 拦截页识别** | 华为云 CloudWAF 式 418"访问被拦截"页明确识别并给出等待指引（区别于可自动应答的 JS 挑战页），绝不尝试绕过 |

### 触发后恢复（熔断与记忆）

| # | 机制 | 作用 |
|---|---|---|
| 15 | **三态熔断** | CLOSED→OPEN（熔断）→HALF_OPEN（单请求探测）→自动恢复；连续 4 轮探测失败才放弃，避免"熔断即永久死亡" |
| 16 | **健康慢恢复** | 限流后并发按 +25%/秒缓慢回升，防止二次触发 |
| 17 | **跨会话域级记忆** | `~/.panboost/antifraud.json` 记住每个域名上次的冷却状态，二次运行自动低并发起步；下载成功自动清除 |
| 18 | **域级并发学习** | AIMD 收敛值随域画像持久化（`cap` 字段），二次运行从学习值起步（保留 2 倍爬升空间）——不再每次重新"挨打学习"该源的并发上限 |

### 验证挑战与可观测

| # | 机制 | 作用 |
|---|---|---|
| 19 | **JS Cookie 挑战自动应答** | v1.4：中科大镜像式"Verifying your browser"页（document.cookie + setTimeout reload）自动解析 cookie、礼貌等待、带 cookie 重试——probe/多线程worker/单线程三路径全覆盖 |
| 20 | **审计日志** | `--explain` 打印会话风控决策摘要；明细 JSONL 追加至 `~/.panboost/antifraud.log`（throttle/ua_switch/challenge_solved/stall_killed/waf_block 等事件） |
| 21 | **数据完整性三重防护** | Content-Range 逐块校验 + `--sha256`/`--md5` 终验自动重下 + 错位响应立即重试 |
| 22 | **测试加速因子** | `PANBOOST_CB_SCALE` 环境变量缩放冷却时长，132 项测试数分钟跑完 |

进度条实时显示引擎状态：`[cap=512/1024]`（当前并发上限）或 `[cap=256 冷却12s]`（冷却倒计时）。

**合规边界**：引擎的定位是"让礼貌的客户端更安全"——降低误触发风控的概率、触发后优雅恢复，
保护**你自己登录的账号**。不提供、也不会提供代理池轮换 / IP 轮换 / 账号切换等"绕过封禁"能力：
那属于滥用规避，必然违反网盘服务条款，且会加速账号被封。

## 下载稳定性引擎（v1.5 六件套 + v1.6 两补）

反风控解决"被服务器拒绝"，稳定性引擎解决"服务器半死不拖垮下载"——借鉴 aria2 `--lowest-speed-limit`
与 wget `--read-timeout` 的思路并更进一步（击杀 + 断点续接，而非整块重来）：

| # | 机制 | 作用 |
|---|---|---|
| 1 | **块级看门狗** | `--stall-timeout`（默认 30s）内某块零字节进展即 `shutdown()` 击杀僵尸连接（服务器/中间设备静默丢包、`read()` 永久阻塞的场景），换新连接从断点续传 |
| 2 | **块内断点续传** | 64MB 大块中途失败，重试的 Range 从 `start+已下载字节` 继续，不再整块重来——与看门狗配合，僵尸连接被杀后损失趋近于零 |
| 3 | **进度文件 v3** | `.pbctrl` 记录每块**部分字节**（`parts` 字段），进程被 SIGKILL 也能精确续传；保存前 `fsync` 保证崩溃一致性（`PANBOOST_NO_FSYNC=1` 可跳过提速） |
| 4 | **磁盘预检** | 下载前检查可用空间（含 16MB 预留），不足即提前报错，杜绝"写一半磁盘满"留坏文件 |
| 5 | **全局错误预算** | 连续 16 次网络错误触发全体指数退避（1s→2s→…→10s 封顶），成功一块即清零——服务器半死时不再形成请求风暴 |
| 6 | **单线程 `.pbpart` 续传** | `--single` 模式中断后，重跑同一命令发 `Range: bytes=已下载-` 从断点追加，不再从零开始 |
| 7 | **双进程文件锁**（v1.6） | `fcntl.flock` 锁定输出文件——两个终端对同一文件同时下载时后到者明确报错退出，而非双双"成功"留下交错损坏的数据（压测实测修复前静默损坏） |
| 8 | **探测瞬时限流重试**（v1.6） | 探测期撞上 429/503 不再立即放弃：带退避重试 3 轮并遵守 Retry-After——混沌压测（40% 瞬时错误率）下故障率 100%→0 |

## 性能引擎（v1.6，cProfile 剖析驱动）

32 线程 / 500MB 剖析发现写路径与连接管理是热点，四项优化全部实装并基准验证：

| # | 优化 | 依据 | 效果 |
|---|---|---|---|
| 1 | **Socket 调优** | TCP_NODELAY 禁用 Nagle（小请求包不再等 40ms 合并，TTFB 测量不被污染）；SO_RCVBUF 256KB | 延迟感知降载的测量精度提升 |
| 2 | **写缓冲聚合** | 连续 chunk 攒到 1MB 再 `pwrite`，parts 记账与落盘原子对应（SIGKILL 安全） | pwrite 系统调用 **2048→512 次（-75%）**，`_count_lock` 争用同频下降 |
| 3 | **字节感知连接复用** | 512KB 小块 ×6 = 3MB 即换连接，TLS 握手 + TCP 慢启动开销占比过高；改为服务满 32MB 才换（保留 24 块硬上限的拟人化语义） | 小块高并发场景握手成本摊薄 |
| 4 | **脏标记保存** | 微小块场景（1600 块）progress_loop 每秒全量 JSON 序列化 done_hex 纯属浪费 | 仅在完成位/parts 变化时写盘 |

另附**延迟感知预防性降载**：worker 采样复用连接的 TTFB（EWMA），拥塞（>2.5× 基准）时并发上限
-10%/s 预防性收缩——TTFB 随并发线性上升的拥塞服务器压测中，并发自动收敛且**零限流事件**。

### v1.1 三重数据安全防护

- **Content-Range 完整校验**：每块响应的起点/终点/总长必须与请求完全一致，错位响应立即重试
- **`--sha256` / `--md5` 校验**：下载完成自动校验，不一致自动删除重下（最多3轮），网盘文件务必带上官方哈希
- **UA 自动回退**：探测被 403 拒绝时自动切换 UA 重试（镜像站偏好 curl UA，网盘偏好 Chrome UA）

## 快速开始

```bash
# 推荐：自动测速选线程数 + 官方哈希校验（最稳最快的组合）
python panboost.py download "直链" --auto --sha256 <官方SHA256>

# 手动指定线程数（默认16，最高1024）
python panboost.py download "直链" -t 64

# 带上你的登录 Cookie（网盘直链几乎都需要）
python panboost.py download "直链" --cookie "BDUSS=xxx; STK=yyy"

# 指定 UA / Referer / 输出文件
python panboost.py download "直链" -o 电影.mkv \
    --ua "netdisk" --referer "https://pan.baidu.com/"

# 探测一个 URL 是否支持 Range 分段（返回大小/文件名/ETag）
python panboost.py probe "直链"

# 批量下载：urls.txt 每行一个 URL（# 注释），同域自动礼貌间隔，失败的单独列出
python panboost.py download --input urls.txt -o 下载目录/
```

中断了（Ctrl+C / 断网 / 关机）？**重新执行同一命令**即自动续传，不重复下载已完成部分。

## 全网盘适用：如何拿到"直链 + Cookie"

所有网盘下载到本地时，浏览器/客户端最终都在请求一个 HTTP(S) 直链。
你先登录账号，按下述任一方法拿到直链，交给 PanBoost 即可——**对任何网盘通用**。

### 方法一：F12 网络面板（万能，100% 适用）

1. 浏览器登录网盘网页版，按 `F12` 打开开发者工具 → **网络(Network)** 面板
2. 点击网页上的"下载"按钮
3. 在网络面板里找到体积大的那条请求（通常类型为 `media`/`document`，或域名含 `dlink`/`download`/`cdn`/`pcs`）
4. 右键该请求 → **复制链接地址**（这就是直链）
5. 在该请求的**请求标头**里复制完整的 `Cookie` 值（一大串）
6. 交给 PanBoost：

```bash
python panboost.py download "复制的直链" --cookie "复制的Cookie串"
```

> 百度网盘提示：直链有时效性（数小时），过期后重新登录网页版再取一次即可。

### 方法二：油猴脚本「网盘直链下载助手」（推荐，支持多家网盘一键取链）

1. 浏览器安装 [Tampermonkey](https://www.tampermonkey.net/) 扩展
2. 安装开源脚本 **「网盘直链下载助手」**（GreasyFork 搜索，支持百度/阿里/夸克/天翼/123/移动云等）
3. 登录网盘后页面会出现"下载助手"按钮 → 点击导出直链（有的脚本还能直接推送到 Aria2/IDM）
4. 复制直链 + Cookie，交给 PanBoost（同上）

### 方法三：导出 cookies.txt + 域名记忆（免反复复制）

用浏览器扩展 **"Get cookies.txt LOCALLY"** 导出网盘站点的 cookies.txt，然后：

```bash
# 导入一次，PanBoost 会按域名持久化存储（~/.panboost/cookies.json）
python panboost.py cookie import pan.baidu.com cookies.txt

# 之后下载该网盘直链时自动附带 Cookie，无需再传
python panboost.py download "https://xxx.dlink..."

python panboost.py cookie list     # 查看已导入
python panboost.py cookie remove pan.baidu.com
```

### 方法四：内置解析器（v1.8.0，直接粘分享链接）

三家网盘分享链接已内置自动解析，**直接粘分享链接即可下载**：

| 网盘 | 是否需登录 | 说明 |
|---|---|---|
| 蓝奏云 | 免登录 | 公开分享直接解析 |
| 123云盘 | 免登录 | 公开分享直接解析 |
| 夸克网盘 | 需登录 | 先在 App 首页登录夸克，或 CLI 用 `--cookie`/`--cookie-file` |

```bash
python panboost.py download "https://pan.lanzoux.com/iXXXXXX"
python panboost.py download "https://www.123pan.com/s/AbCdEf"
python panboost.py download "https://pan.quark.cn/s/AbCdEf"          # 自动带已存夸克 Cookie
python panboost.py download "https://www.123pan.com/s/AbCdEf?code=9x8k"  # 带提取码
python panboost.py resolve "https://pan.quark.cn/s/AbCdEf"           # 只解析不下载（列出全部文件与直链）
```

- 提取码写在链接后：`?code=xxxx`（或 `#xxxx`）
- **多文件分享自动批量下载**：`-o` 指定输出目录，逐文件下载、同域
  礼貌间隔、失败文件列清单可重跑（断点续传自动跳过已完成文件）
- 夸克直链下载自动携带 Cookie 与 Referer（网页端同款行为）
- 其他网盘解析器可在 `panboost.py` 的 `RESOLVERS` 注册表按示例扩展
  （`resolve_pan123` 为推荐模板：API 基址可被 `PANBOOST_RESOLVER_HOSTS`
  环境变量覆盖，便于离线测试）

## 常用参数

```
download <URL>
  -o, --output FILE    输出路径（默认取服务器文件名/URL名）
  --input FILE         批量模式：从文本文件读取 URL 列表（每行一个，#注释），
                       此时应给 -o 目录；失败的文件汇总列出，重跑自动跳过已完成
  -t, --threads N      线程数，默认16，最高1024（配合反风控引擎可安全使用高线程）
  --auto               下载前实测1连接/16连接吞吐，自动选择线程数（速度最优解）
  --conn-rate N        新连接建立速率上限/秒，默认64（反风控令牌桶）
  --sha256 HASH        期望SHA256，下载后自动校验，不一致自动重下
  --md5 HASH           期望MD5，同上
  --min-piece N        块大小下限，默认512KB（动态分块引擎自动调整）
  --retry N            块失败重试次数，默认8（指数退避+抖动）
  --stall-timeout SEC  块级看门狗：无进展超时击杀僵尸连接，默认30（0关闭）
  --cookie "k=v;..."   Cookie 请求头（优先级最高）
  --cookie-file FILE   Netscape cookies.txt（一次性使用）
  --ua STR             自定义 User-Agent（默认Chrome UA；被拒时自动回退其他UA）
  --referer URL        Referer（部分网盘校验来源）
  --header "X: Y"      任意额外请求头，可多次
  --single             强制单线程
  --limit RATE         全局限速（如 4M / 512K），令牌桶整形总吞吐
  --no-persona         关闭拟人化请求头（排障用）
  --explain            结束时打印本会话反风控决策摘要
  --insecure           跳过TLS证书校验（个别网盘CDN证书异常时用）
  --quiet              静默模式
```

## 常见问题

| 现象 | 原因与解决 |
|---|---|
| `服务器拒绝访问(403)` | 直链缺 Cookie 或过期：重新登录取链；或补 `--referer`/`--ua`（未指定UA时会自动回退重试） |
| `期望206，得到 200` | CDN 忽略了 Range，PanBoost 会自动重试；持续出现则加 `--single` |
| 速度仍不理想 | 用 `--auto` 实测该源有效并发；网盘类可试 `-t 64/128` |
| 直链失效 | 网盘直链普遍带签名和时效，过期重取；PanBoost 支持随时中断续传 |
| 下载到一半换网 | 直接重新执行同一命令，Range 续传从断点继续 |
| 校验失败 | 高并发下源返回过损坏数据：降低线程数重试；给官方哈希让 PanBoost 自动重下 |
| 进度条显示 `冷却xxs` | 反风控引擎收到限流信号正在冷却，属正常自适应行为，无需干预 |
| `持续403：服务器已封锁` | 连续403触发熔断：进度已保存，等一段时间再续传，或重新登录取新直链 |
| 下载卡在"Verifying"后失败 | v1.4 已能自动应答中科大式 JS cookie 挑战；若服务器用更复杂的验证（如华为云 CloudWAF 418 硬拦截，属 IP 信誉判定），换网络环境或稍后再试 |
| 收到 HTTP 418 | 多为 CDN/WAF 将高并发判定为攻击（如华为云 CloudWAF）：v1.5 已能**识别拦截页并给出等待指引**，进度已保存；等冷却或降低 `--conn-rate`/线程数再试 |
| 下载中途卡住不动 | 服务器/中间设备静默丢包：看门狗 30s 无进展自动击杀僵尸连接、换新连接从断点续传；保守/激进可用 `--stall-timeout` 调整 |
| 服务器持续 429 不放行 | v1.5 无进展熔断：30s 零成功块即熔断退出并保存进度（不再无限重试挂死），稍后重跑同一命令续传 |
